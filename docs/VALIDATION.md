# v0.1.0 validation

Validated on 2026-11-11 (Japan time).

- Local Windows x64 build with Rust 1.99.1 and the MSVC toolchain.
- `cargo test --locked --all-targets`: 16 integration tests passed.
- `cargo fmt --all -- --check`: passed.
- `cargo clippy --locked --all-targets -- -D warnings`: passed.
- `cargo build --locked --release --bins`: passed for both GUI and CLI.
- [GitHub CI](https://github.com/conmmitmentman/jxl-studio/actions/runs/42841397658): Windows and Ubuntu both passed.

The actual portable Windows GUI was opened and used to select the original
960 × 640 sample generated by `examples/sample.rs`, convert it to JXL, display
the resulting JXL, switch between fit and 100% display, and return to fit.
The portable CLI exported that GUI-generated JXL as a PNG successfully.
`screenshot.jpg` shows the converted JXL in the application.

Round-trip tests use zune-jpegxl encoding and the independently implemented
jxl-oxide decoding. Coverage includes all eight supported integer pixel layouts,
transparent samples, upper-range 16-bit gray/alpha values, tiny/odd/group-boundary
dimensions, every advertised input format, EXIF orientation, Japanese file names,
no-clobber saves, corrupt files, PNG export, and actual CLI processes.

Animations, HDR output, arbitrary input ICC profile preservation, and native
macOS behavior were not validated and are outside this release's supported scope.
